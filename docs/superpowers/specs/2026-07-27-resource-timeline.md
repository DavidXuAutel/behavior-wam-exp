# 训练资源与周期评估

> Date: 2026-07-27  
> Basis: `docs/superpowers/specs/2026-07-27-train-eval-scheme.md`  
> Assumptions: Wan2.2 **5B-class** + LoRA；A0 冻 Video；A1c/B locked-same 各跑一轮；主子集先 5–10 tasks，再视门禁扩量

**Disclaimer:** 下列为工程估算区间，非实测。Week 0 smoke 后应以 `reports/benchmark_train_step.json`（单步 ms、显存）重标定。

---

## 1. 结论摘要

| 档位 | GPU | 日历周期（到可提交包） | 粗算 GPU·小时（主训） | 存储（热数据） |
|------|-----|------------------------|----------------------|----------------|
| **最小可行（MVP）** | 4× A100 80G 或 4× H100 | **6–8 周** | **1.5k–3k** | **6–10 TB** |
| **推荐（Base）** | **8× A100/H100 80G** | **8–10 周** | **4k–8k** | **10–15 TB** |
| **加速 / 全量冲刺** | 16–64× H100 | **4–6 周**（并行） | **8k–20k+** | **15–25 TB** |

Challenge 截止 **2026-10-16**；自 2026-07-27 起约有 **11–12 周**。  
→ **Base 档在窗口内可完成**；MVP 偏紧但可行；全量 100 任务重训 + 完整 E5 需 Base 以上并尽早开评测并行。

**不推荐：** 单卡 24GB 做 A1c/B 主训（可做冒烟，不可做主路径）。

## 2. 存储需求

| 资产 | 量级 | 备注 |
|------|------|------|
| 官方 LeRobot demos | **~3.3 TB** | 必挂；可冷存远端 |
| 官方 raw HDF5（可选） | **~1.4 TB** | 仅 D2 replay 扰动需要 |
| Wan2.2 DiT+VAE+UMT5 | **~50–120 GB** | 视具体包；另加 HF 缓存 |
| 技能段缓存（5–10 tasks） | **0.3–1.5 TB** | 预编码 latent 可再 ×1.5–2 |

| Checkpoints / 日志 | **0.2–1 TB** | A0+A1c+B+C + 中间 ckpt |
| On-policy + 失败集 | **0.2–1 TB** | D2 |

IO 建议：demos 走并行文件系统/NAS；训练节点本地 NVMe 放 latent cache + ckpt。

## 3. 算力与显存

### 3.1 单卡显存画像

| 模式 | 配置假设 | 单卡显存 |
|------|----------|----------|
| A0 FAST（Video 冻，训 Action+Perceiver） | 1–2 视角 @256，bs=1–2 | **24–40 GB** 可试；稳妥 **40–80 GB** |
| A1c/B FULL（Video LoRA + 未来 latent） | 1–2 视角 @256，bs=1，grad ckpt | **稳妥 80 GB** |
| 三视角 @384 FULL | bs=1 | 易顶满 **80 GB**；需降视角/分辨率或序列并行 |

**推荐训练单元：** 8×80GB（A100/H100），ZeRO-1/2 或 FSDP。

### 3.2 分阶段 GPU·小时（Base 假设）

假设：

- 主训子集：约 **5–10 tasks**，有效技能段 ~**5e4–2e5** 窗（过采样后）
- A0：~**30k–80k** steps
- A1c / B：各 ~**50k–100k** steps，FULL:FAST=0.5（B 与 A1c **各跑满** → ≈×2）
- Stage C：~**10k–30k** steps
- 8×80GB，有效吞吐按「单卡 step 折算」给出区间

| 阶段 | GPU·小时（低） | GPU·小时（中） | GPU·小时（高） | 墙钟（8 卡） |
|------|----------------|----------------|----------------|--------------|
| D0 审计/切片（CPU+轻 GPU） | 50 | 100 | 200 | 2–5 天 |
| Planner v0 | 20 | 40 | 80 | 0.5–1 天 |
| A0 | 200 | **400–800** | 1200 | 2–5 天 |
| A1c | 400 | **800–1500** | 2500 | 4–8 天 |
| B（与 A1c 对称） | 400 | **800–1500** | 2500 | 4–8 天 |
| D2 采数（仿真为主） | 100 | 300 | 600 | 3–7 天（可与写报告重叠） |
| Stage C | 80 | **200–400** | 700 | 1–3 天 |
| **主训小计** | **~1.3k** | **~3.5–6k** | **~10k+** | |

**关键乘数：**

- 视角 1→3：≈ **×1.5–2.5**（视 concat 方式）
- 分辨率 256→384：≈ **×1.5–2**
- 数据从 10 tasks → 全 100：steps/数据量 ≈ **×5–10**（不建议 W2 前做）
- A1c+B 必须成对：主路径算力 ≈ **2 × 单组 LoRA 混合训**

### 3.3 评测算力（常被低估）

OmniGibson 闭环通常 **仿真瓶颈 > 策略推理**：

| 套件 | 规模 | 粗估墙钟（8 仿真 worker） |
|------|------|---------------------------|
| E0 | 1×1 | 小时级 |
| E1 | 5×10=50 | **0.5–2 天** |
| E2 | ~同量级 | **0.5–2 天** |
| E3 | E1 × 扰动重复 | **1–3 天** |
| E4 基线 | 同 E1 | **1–2 天**（另环境） |
| E5 Full | 1000 rollouts | **1–3 周**（需尽早开跑、可部分提交） |

推理本身：FAST 5 步去噪，单卡 4090/A100 达 **3–5 Hz** 目标通常可行；瓶颈在渲染与物理。

## 4. 人力与日历周期

自 **2026-07-27** → DDL **2026-10-16** ≈ **11.5 周**。

### 4.1 推荐排期（Base：8 GPU）

| 周 | 工作 | 出口 |
|----|------|------|
| W0–1 | 环境、model_lock、E0、D0 审计 | 可训 |
| W2 | Planner + A0 + 初 E1 | A0 可闭环 |
| W3 | Hier vs Flat | Hier 门禁 |
| W4–6 | A1c ∥ B（可两节点并行则压到 ~2 周） | B 门禁 |
| W6–7 | D2 采数 + E2/E3 | 泛化报告 |
| W7–8 | Stage C + E1/E2/E3 复测 | C 门禁 |
| W8–11 | 扩任务覆盖、E4、E5 分批提交 | 提交包 |

**并行技巧：** A1c 与 B 用两台 8 卡同时跑 → 墙钟约减半；评测集群与训练集群分离。

### 4.2 风险缓冲（必留）

| 风险 | 额外时间 |
|------|----------|
| Hier 不过，迭代 Planner/完成检测 | +1–2 周 |
| A1c≈B，回退修数据/对齐 | +1–2 周 |
| OmniGibson 不稳定 / 评测排队 | +1 周 |
| 数据 IO / 切片返工 | +3–5 天 |

→ 规划上按 **「8 周干完主路径 + 3 周缓冲/扩量」** 更稳。

### 4.3 人力

| 角色 | 投入 |
|------|------|
| 训练/模型 | 1 人全职 |
| 仿真评测/数据 | 0.5–1 人 |
| 基建（存储/调度） | 0.25 人 |
| **合计** | **~2 FTE** 为 Base；1 FTE 则周期 ×1.3–1.5 |

## 6. 降级与升级策略

**保门禁顺序：** D0 → A0 → Hier → **A1c+B on E2** → C → E5  

**可砍：**

1. 三视角 → 先 head（+可选 1 wrist）  
2. 256 而非 384  
3. E3 全因子 → 先 lighting+depth+delay  
4. E4 完整基线 → 只报公开数字或抽测  
5. 100 任务全量重训 → 门禁过后再扩  

**不可砍：** A1c 与 B 成对；episode 防泄漏；E2 held-out scene。

## 7. Week 0 必须实测的标定项

写入 `reports/resource_calibration.json`：

```text
- FAST / FULL 单步 ms（1/2/3 视角 × 256/384）
- 峰值显存 GB
- 单卡最大 micro-batch
- 8 卡 samples/sec
- E1 单 episode 墙钟（含仿真）
- 磁盘顺序读 demos MB/s
```

用实测重算 §3.2；偏差 >2× 则改排期或降配置。

## 8. 一句话

**推荐 8×80GB、热存 10–15TB、日历 8–10 周主路径（DDL 前留 2–3 周缓冲）；主成本在成对的 A1c/B 与 OmniGibson 大规模评测，不在 Planner。**
